# 测绘准确性铁律 (实战教训浓缩)

口径: **准确性 > 数量**。一条错归属资产比漏十条更伤报告可信度。

## A. 归属判定

1. **优先级链**: 子域例外表(sub_overrides) > 域名后缀匹配 > ICP 主体匹配 > 集团域范围外 > 未知(范围外)。
   集团遗产域(如集团主域)下的子域**默认范围外**, 除非授权书明示或例外表点名。
2. **ICP 匹配必须剥尾序号**: `京ICP备18041247号-1` → 按 `京ICP备18041247` 前缀比对。
3. **ICP 归属但域名不在主域表** → 标记"需人工确认", 不得直接算范围内 (开发商代备案/共享主体是常态)。
4. **范围外主体要显式剔除并留痕**: 例: 资产表里出现兄弟集团域名(共用历史备案), 在测绘说明里写明剔除理由。

## B. 假阳性四类 (全是实战踩过的)

1. **伪造备案号**: 赌博/私彩站批量伪造央企备案号, IP 集中 154.x/156.x/179.x 海外段, 标题博彩词。s5 自动剔; 终判看主体。
2. **泛解析**: 随机子域双探针解析出同 IP → 泛解析; 其子域解析到泛解析 IP 一律视为假存活剔除。
3. **tarpit / 端口黑洞**: 某些 IP 全端口开放全应答, 是诱捕或运营商黑洞; 特征: 端口扫描结果"全开"+ banner 无差异。测绘阶段把"端口全开"的资产标记待复核, 别直接当资产。
4. **CDN/云 WAF 出口**: 一堆域名解析到同一 CDN IP; C 段推演只对"独占 IP"做, CDN IP 不算资产本体。

## C. 指纹识别假阳性 (s6 阶段)

1. **SPA 路由 fallback**: Vue/React 单页应用任意路径都返回 200+同一 HTML → 关键词规则全命中。处置: 命中规则前先比对"请求路径是否出现在响应里"(路径回显=模板渲染, 不是真存在)。
2. **302 跳转回显**: 跳转页 Location 含探测词 → 误判。处置: 302 只认 Location 指向登录/已知路径。
3. **JSON 404 回显**: API 网关对未知路径回 200+`{"code":404}` → 误判。处置: 看 body 是否含 code/message 错误结构。
4. **关键词过泛**: "nginx"、"iis"、"login" 这类不得单独作为产品指纹; 必须组合特征(web容器+版本号 或 路径+确认词)。
5. **验证判定法**: 指纹命中只算"疑似", 高价值目标(能打点进报告的)必须人工 curl 复核响应原文再定。

## D. 平台数据口径

1. **多源互补不互信**: 同一资产 Hunter 有 FOFA 无是常态 (时间窗/采集面不同); 合并字段、来源留痕 (source_tag)。
2. **平台快照≠现状**: 平台 title/状态码是采集时刻的; 交付前对高关联资产做一次实时探测刷新 (s6 的 root 探测即为此)。
3. **DNS 已删除≠资产死亡**: 平台库存+A记录消失的目标, 用 `--connect-to host:443:IP:443` 直达验证; 实战多次打中"DNS下线服务在线"的靶标。
4. **配额纪律**: 每查询打印剩余配额; Hunter 积分/FOFA F点/Quake credit 见底要通知用户充值, 不要闷头烧完。断点续跑 ([skip]) 必须保留。

## E. Excel 交付规范 (s7)

- 五表: 测绘总表(逐资产) / 域名清单(逐主域) / 子域名清单(DNS存活) / 单位汇总(管理层视角) / 测绘说明(方法论+准确性控制+局限, **必填**)。
- 配色语义固定: 高关联=橙, 范围外=灰, 新发现/泛解析=绿; 加筛选+冻结首行。
- 测绘总表必须含: ICP备案号/备案单位/数据来源/备注(归属依据) 四列 — 这是"准确性可审计"的关键。
- 局限性一节如实写: 内网型系统无公网暴露、平台采样深度、crt.sh 失败域、待人工确认项。

## F. 授权纪律 (不可妥协)

- scope.json 的 units 即白名单; 每个阶段脚本只处理 in_scope 资产。
- 集团域范围外资产: 测绘表可见(灰底)但**不探测不打点**。
- 弱口令/打点/上传类动作超出本 skill 范围, 走各自的攻击 skill 和授权流程。
