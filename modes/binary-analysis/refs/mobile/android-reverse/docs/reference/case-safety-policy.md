# Case Safety Policy

- 仅处理用户明确授权或训练/CTF/样本环境中的目标
- 不主动执行未授权漏洞利用、持久化、投递、横向移动
- 任何会改写真实设备状态、真实账号态或真实网络环境的动作，都必须在 `boundaries` 中明确记录
- 结论必须可回指文件、函数、调用链、日志、hook 输出或其他原始证据
- 动态实验若存在破坏性风险，必须先记录风险点，再等待用户确认

本技能明确不覆盖：

- 普通 Android 开发
- 未授权漏洞利用
- iOS 逆向

## 新 SO 工具逆向确认

需要用反编译/反汇编工具分析一个新的 `.so` 前，若用户没有明确说"直接分析 / 继续 / 已授权 / 无需确认"，默认先走确认流程——向用户说明以下内容，等待确认后再执行工具逆向：

- 目标 `.so` 与分析目的
- 计划使用的工具（`.so` 反编译/反汇编强制使用 IDA；只有用户明确表示没有 IDA 或无法提供路径后，才允许 Ghidra/radare2/objdump 回退，并记录答复与原因）
- 预计产物（反编译文本、函数范围、伪代码、调用图）
- 是否需要先判定磁盘 SO 加密/壳化/自解密/运行时重建（见 `references/so-runtime-evidence-playbook.md` §1）；若命中，dump/fix 是硬约束，必须先抓运行期 SO 再分析，禁止直接分析磁盘 SO

用户已经提供 IDA 导出、明确要求"直接分析导出"、或基于已有产物继续时，可以直接推进并同步记录。

## 记录边界（防结论失真）

- 不把猜测写成确认
- 不把 helper（字符串解码、日志、加密工具函数）误记为检测入口
- 不把一次未命中写成"不存在"
- 不覆盖旧记录，不丢失失败轮次——失败轮次常提供最关键的边界信息
- 所有已分析出的检测/校验代码都要记录 so/函数/offset、判断条件、常量/字符串、syscall/API、返回值/状态码、fatal/kill/abort/BRK 分支与上下游调用，不得只写一句"检测 Frida/Root/CRC"
