# Pure Extraction

进入 `PureExtraction` 前，至少先满足：

- 关键证据已捕获
- 本地重建或最小复现已稳定
- 能明确划分”平台噪音”和”纯算法 / 纯逻辑”边界

## 进入判定标准（操作化）

满足以下全部条件时允许进入：

1. **证据闭环**：至少一条切入点产出完整证据链（输入 → 处理 → 输出），且至少 2 个不同输入样本验证通过
2. **复现稳定**：本地复现脚本对相同输入产出相同输出，连续 3 次无偏差
3. **噪音可识别**：能列出”平台相关项”清单（如 Android API 调用、设备状态读取、进程间通信），且这些项与核心算法/逻辑无关

## “平台噪音” vs “纯算法/逻辑”判定

- **平台噪音**：依赖 Android API（Context / SharedPreferences / TelephonyManager）、设备状态（build fingerprint / screen size）、运行时环境（SELinux / process UID）的操作
- **纯算法/逻辑**：仅依赖输入参数和常量（密钥 / IV / 盐值 / 算法标识）即可独立计算的部分
- **灰色地带**：从设备属性派生的参数（如 ANDROID_ID 用于密钥派生）——记录派生方式，将派生参数视为算法输入而非平台依赖

## 进入后

- 只保留与业务结果直接相关的计算路径
- 删除临时 hook、旁路日志和与最终交付无关的 patch
- 将平台相关参数替换为可配置输入（从配置文件 / 环境变量读取）
- 若可移植，再进入 `Port`
