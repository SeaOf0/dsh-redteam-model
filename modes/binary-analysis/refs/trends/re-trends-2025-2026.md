# 2025–2026 二进制逆向趋势速览（binary-analysis 侧）

> 本文件为自建综述，条目均于 2026-08-16 联网核实，附来源。
> 用途：开工前校准工具链与方法论新鲜度；与 refs/ 各手册配合。

## 1. 主线架构：agent-on-top-of-decompiler

- 2025–2026 的收敛形态：Ghidra/IDA 产出伪代码，AI agent 在其上做解释、命名、
  导航与批注——不是用 LLM 替代反编译器，而是把反编译器变成 agent 的工具。
- 与本模式的关系：本模式（DSH + playbook + 子代理）本身就是这个架构的实现；
  refs/tools/ 的 ida/ghidra/r2 手册即「反编译器侧」，agent 编排在 persona。

## 2. MCP 成为 LLM↔逆向工具的标准桥

- **ida-pro-mcp（mrexodia）**：IDA Pro 的 MCP server，LLM 直接驱动 IDA 分析。
  https://github.com/mrexodia/ida-pro-mcp
- **Ghidra MCP（LaurieWired）**：Ghidra 的 MCP 桥接。
- **ReVa（Reverse Engineering Assistant）**：Ghidra MCP server，让 AI 模型操作
  Ghidra 的分析能力。https://github.com/cyberkaida/reverse-engineering-assistant
- **对本模式的含义**：与项目既定的「MCP 加载插件」路线对齐——
  逆向工具链经 MCP 接入后，本模式的工具平面即可直连 IDA/Ghidra；
  在那之前按三级兜底走 bash 命令行（playbook 工具手册）。

## 3. 研究与工作流

- **DecLLM**（ACM 2025）：LLM 增强的**可重编译**反编译研究——伪代码不仅可读，
  还能通过编译还原等价二进制，提升保真度。https://dl.acm.org/doi/10.1145/3728958
- **Cisco Talos《LLM as a reverse engineering sidekick》**：把 LLM 当恶意分析
  副驾驶的实操工作流（分类、字符串研判、配置提取）。https://blog.talosintelligence.com/using-llm-as-a-reverse-engineering-sidekick/
- 商业侧：RevEng.AI 等二进制智能平台（IDA/Ghidra/Binary Ninja 插件）。
  https://reveng.ai/
- **纪律提醒（本模式硬规则）**：LLM 输出是「待验证假设」——函数命名/行为判断
  必须落到字节/指令级证据（虚拟地址/偏移/反汇编片段），与 persona 证据标准一致。
