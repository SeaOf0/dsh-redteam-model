# 制品仓库投毒与签名绕过

> 定位：制品仓库（镜像仓库、包仓库、二进制制品库）是 CI/CD 的「交付枢纽」，也是投毒的最
> 后一公里。本手册梳理制品仓库访问缺陷、制品投毒、签名绕过与只读探测，每条路径配检测侧
> 对照。破坏性步骤标「授权内人工确认后执行」。

## 1. 攻击面

制品仓库攻击面：

| 面 | 形态 | 风险 |
|---|---|---|
| 访问面 | 匿名/越权拉取、公开制品 | 内部制品与密钥泄露 |
| 写入面 | 越权推送、可变标签覆盖 | 投毒制品被生产拉取 |
| 签名面 | 未签名、签名密钥泄露、验签缺失/可绕过 | 篡改制品无法识别 |
| 元数据面 | SBOM/溯源缺失、依赖混淆 | 供应链溯源断裂 |

核心风险：生产运行时按「标签」拉制品，若标签可变（`latest`）且验签缺失，替换制品即可
投毒生产，且难以溯源。

## 2. 暴露面探测（只读命令优先）

### 2.1 制品仓库匿名/越权只读探测

```bash
# 镜像仓库（同容器供应链手册）
curl -s -o /dev/null -w '%{http_code}' https://<registry>/v2/
curl -s https://<registry>/v2/_catalog                      # 匿名可列镜像 = 高危
curl -s https://<registry>/v2/<image>/tags/list
# 包仓库（npm/PyPI/Maven 私有源）匿名拉取探测
npm view <pkg> --registry https://<registry> 2>&1 | head    # 只读查询
```

判定口径：匿名可 `_catalog`/拉包 = 制品面公开；能读私有制品 = 内部制品泄露。

### 2.2 制品标签与 digest 只读盘点

```bash
docker inspect <image> --format '{{.RepoDigests}}'   # 是否 pin digest
docker trust inspect --pretty <image> 2>/dev/null    # 签名状态
# 包仓库：看制品是否带 provenance/签名元数据（只读查询）
```

判定口径：无 RepoDigests 或无签名 = 无法证明制品未被篡改。

### 2.3 SBOM 与溯源只读盘点

```bash
# 生成/读 SBOM（本地只读，不外传）
syft <image> -o json 2>/dev/null | head
grype <image> 2>/dev/null | head
```

判定口径：无 SBOM/溯源 = 无法定位制品内的组件与漏洞，登记供应链盲区。

## 3. 缺陷与利用路径

### 3.1 制品仓库匿名可写 / 越权推送

- 缺陷：仓库写权限未鉴权或绑定过宽，攻击者可推送恶意制品、覆盖标签。
- 验证命令（只读）：读仓库 ACL/策略看可写主体；`docker login` 探测匿名推送是否被拒
  （登录属只读探测，不实际推送）。
- 影响：投毒制品进仓库，被下游拉取。
- 检测侧：仓库访问审计（异常 push/匿名推送）；推送事件审计（谁推了什么标签）；签名验签
  失败记录。

### 3.2 可变标签覆盖投毒（`latest` 漂移）

- 缺陷：生产按 `latest`/可变标签拉取，攻击者覆盖标签指向恶意镜像，无需改部署配置。
- 验证命令（只读）：`docker inspect --format '{{.RepoDigests}}'` 看是否 pin digest；仓库
  tags 列表与部署清单比对。
- 影响：运行时拉取被投毒的镜像。
- 检测侧：仓库推送审计（标签覆盖事件）；部署侧拉取审计（digest 漂移告警）；运行时异常
  行为检测。

### 3.3 签名密钥泄露 / 验签缺失

- 缺陷：签名私钥（Cosign/Notary key）泄露或未启用签名；验签步骤被跳过或配置错误（如
  `--allow-insecure`）。
- 验证命令（只读）：读验签配置（准入控制器验签策略、CI 验签步骤）；`docker trust inspect`
  看签名状态。
- 影响：攻击者可用泄露密钥给恶意制品签名，或利用验签缺失直接投毒。
- 检测侧：验签失败/缺失日志；密钥使用审计；准入控制器拒绝事件（若验签开启）。

### 3.4 依赖混淆（同名抢注内部包）

- 缺陷：内部私有包名被公共源抢注（同名高版本），构建时 `pip/npm` 解析到恶意公共包。
- 验证命令（只读）：依赖清单比对私有源与公共源同名包；构建日志看实际解析目标。
- 影响：恶意包进制品与生产。
- 检测侧：SCA 告警；构建日志解析目标审计；私有源访问审计。

### 3.5 制品元数据/溯源缺失导致的检测盲区

- 缺陷：制品无 SBOM/provenance，出事后无法定位受影响组件与范围，检测滞后。
- 验证命令（只读）：SBOM/provenance 只读盘点（见 2.3）。
- 影响：响应面扩大，无法快速止血。
- 检测侧：这是「检测能力的检测」——对溯源体系做覆盖率评估，登记 `detection-gap.md`。

### 3.6 制品缓存/CDN 投毒（分发末端替换）

- 缺陷：制品经 CDN/边缘缓存分发，缓存被投毒或配置错误，末端拉取到被替换的制品。
- 验证命令（只读）：核对边缘分发制品 digest 与源仓库；读分发缓存配置与上游映射。
- 影响：末端消费者中招，溯源困难。
- 检测侧：分发层访问审计；制品 digest 漂移告警；运行时异常行为检测。

## 4. 提权与持久化

- 提权链：制品投毒 → 生产运行时后门 → 容器逃逸/云账号（见容器手册）；签名密钥泄露 →
  持续给恶意制品签名。
- 持久化（授权内人工确认后执行）：在仓库留恶意制品/标签、投毒私有包源、保留签名密钥
  副本；逐项登记 `environment-restore.md`。

## 5. 检测与加固要点

### 5.1 检测事件名对照

| 攻击行为 | 检测层 + 事件 |
|---|---|
| 匿名/越权推送 | 仓库访问审计 + 推送事件审计 |
| 标签覆盖 | 仓库推送审计（标签覆盖）+ 拉取 digest 漂移告警 |
| 验签失败/缺失 | 验签日志 + 准入控制器拒绝事件 |
| 依赖混淆 | SCA 告警 + 构建日志解析目标审计 |
| 签名密钥滥用 | 密钥使用审计 + 签名事件审计 |

### 5.2 加固要点

- 仓库鉴权 + RBAC；写权限最小化；禁匿名推送；私有制品私有化。
- 生产按 digest 拉取，禁 `latest`；启用签名（Cosign/Notary）+ 准入/运行时验签。
- 签名密钥安全托管（KMS/HSM），与 CI 分离；验签强制不可跳过。
- 私有包源 + 依赖锁定 + 依赖混淆防护；全量 SBOM/provenance + 溯源。
