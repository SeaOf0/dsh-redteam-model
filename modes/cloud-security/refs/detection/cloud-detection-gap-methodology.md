# 云检测缺口分析方法论（三态判定 ↔ C5 门）

> 定位：检测侧第三手册，C5「检测缺口评估」的判定方法。回答「这条攻击路径在目标云环境里
> 检测到没有」，并把结论编码成 C5 门要求的终态。判定口径与「发现 ≠ 真实」主观念一致：
> 检测侧结论也必须有证据支撑（日志存在 + 投递 + 规则 + 留存），不凭印象。

## 1. 三态判定模型

对每条攻击路径，站在**防守方能否发现**的立场判三态（+ 一补充态）：

| 态 | 含义 | 判据 |
|---|---|---|
| 检测到（covered） | 该路径的关键动作会留下日志，且目标环境有规则/告警能发现 | 日志存在 + 已投递 + 已启用规则/告警 |
| 未检测到（gap） | 关键动作本应留日志，但日志缺失/未投递/无规则，防守方发现不了 | 三者缺一即缺口 |
| 无法评估（unknown） | 因授权范围/信息不足，无法确认日志或规则是否存在 | 看不到审计配置或 SIEM 规则 |
| 不适用（N/A） | 该攻击路径不涉及本目标环境（如无 K8s 则容器逃逸路径不适用） | 目标无对应资源/服务 |

> 注意：只有「未检测到」是真正的检测缺口；「无法评估」是诚实降级（不冒充有结论）；
> 「不适用」跳过该路径的检测侧评估。

## 2. C5 门编码映射

C5 门要求 `detection-gap.md` 对「云审计/日志/监控缺失面」逐项登记终态三选一
（gap=1 / 无法评估=0 / 不适用=2）。映射关系：

| 判定态 | C5 终态编码 | 是否进「缺失面」清单 |
|---|---|---|
| 未检测到 | `gap=1` | 是（写入缺口清单，附缺失原因与建议规则） |
| 无法评估 | `0` | 是（写入，标注「待确认」，附需补充的证据） |
| 不适用 | `2` | 否（登记不适用理由即可） |
| 检测到 | 无缺口（可记 `covered`） | 否（可记录已覆盖，不进缺口清单） |

## 3. 判定流程（每条路径走一遍）

1. **列出该路径的关键动作**：从攻击路径四要素拆解——入口身份执行了哪些 API/操作
   （如 AssumeRole → 读凭证 → PutBucketPolicy → 公开读取）。
2. **查「应留日志」**：对照 `cloud-audit-log-systems.md` 确认每个动作是否属于控制面
   （默认留痕）还是数据面（默认不留痕/需开启）。
3. **查「日志在不在」**：目标环境该厂商的审计服务是否开启？数据面日志（对象存储读取）
   是否显式开启？是否组织级覆盖（多账号/订阅/项目）？
4. **查「投没投、留没留」**：是否投递到 SIEM/长期存储？留存是否满足取证周期？
   是否防篡改（见 `cloud-monitoring-alerting-baseline.md` 投递完整性检查）？
5. **查「规则有没有」**：对照 `cloud-detection-rule-design.md` 确认是否存在对应告警规则、
   规则是否启用、是否接入告警通道。
6. **落终态**：三步（日志/投递留存/规则告警）全满足 → 检测到；任一缺 → 未检测到；
   无法查证 → 无法评估；路径不涉及 → 不适用。
7. **登记**：把结论与证据写入任务工作区的 `detection-gap.md`（模板见第 6 节）。

## 4. 四要素检测侧检查点（身份→权限→资源→影响）

| 要素 | 应留的日志 | 常见缺口 |
|---|---|---|
| 身份（入口） | 身份侧：凭证获取/登录事件、GetCallerIdentity、SSO 登录 | 无身份审计（Entra 未投递、RAM 未开） |
| 权限（提权/切换） | AssumeRole/actAs/roleAssignments、策略变更、新建凭证 | 控制面日志未投递、无 IAM 变更告警 |
| 资源（目标） | 桶策略/ACL 变更、对象读取（数据面）、DB/密钥访问 | 数据面日志未开（对象级读取盲区） |
| 影响（结果） | 读取/写入/删除的响应、影响面（下载量、脱库量） | 数据面事件未记录 → 影响不可证 |

## 5. 常见判定陷阱

- **「日志存在」≠「检测到」**：只开审计但没投递、没规则，防守方仍发现不了 → 未检测到。
- **「控制面有事件」≠「覆盖数据面」**：对象存储公开读取是数据面动作，控制面日志看不到，
  若数据面日志未开 → 该路径未检测到。
- **「厂商默认留痕」≠「长期可取证」**：默认控制台保留期短，事后取证需投递归档。
- **元数据 SSRF 特殊性**：实例内访问 169.254.169.254 通常不产生控制面事件，检测靠
  VPC Flow Logs / 主机 agent / 应用日志——这些若未配，该路径判「未检测到」。
- **不把「规则缺」掩盖为「无法评估」**：能查到规则不存在就判未检测到，别用无法评估兜底。

## 6. detection-gap.md 登记模板

工作区产物 `detection-gap.md` 每行一条缺失面（或路径检测侧结论）：

```
| 攻击路径/缺失面 | 关键动作 | 应留日志(厂商/事件) | 日志有无 | 投递留存 | 规则告警 | 终态(gap=1/0/2) | 证据 |
| AK/SK 泄露→OSS 读取 | GetObject(数据面) | 阿里云 ActionTrail 数据事件 | 无(未开) | — | — | gap=1 | 控制台数据事件开关截图 |
| 元数据 SSRF→角色接管 | 实例内 IMDS 访问 | VPC Flow + 主机 agent | 未配 | — | — | gap=1 | 无 Flow Log |
| 容器逃逸(无 K8s) | — | — | — | — | — | 2(不适用) | 目标无 K8s 集群 |
```

## 7. 判定证据清单（每态需要什么证据）

| 判定态 | 必须收集的证据 | 缺失时的处理 |
|---|---|---|
| 检测到 | ①审计服务开启截图/导出 ②投递配置（SIEM 目标/留存）③对应告警规则存在且启用的证据 | 证据不齐降级为「无法评估」，不得强判检测到 |
| 未检测到 | ①日志缺失的直接证据（数据事件开关关闭/无投递）②规则缺失证据（SIEM 无对应规则/告警未启用） | 至少一条直接证据才判 gap，避免「没见过」误判 |
| 无法评估 | 记录「缺什么证据」：如无 SIEM 只读权限、无控制台只读权限 | 把待补充证据写入 detection-gap.md 待确认项 |
| 不适用 | 目标环境无对应资源/服务的证据（如无 K8s 集群） | 写明不适用理由 |

## 8. 判定示例（AK/SK 泄露 → 对象读取）

- **关键动作**：`GetObject`（对象存储数据面读取）+ 前置的 `GetCallerIdentity`（身份确认）。
- **应留日志**：控制面 `GetCallerIdentity`（默认留）；数据面对象级读取（默认**不**留，需开启
  数据事件/访问日志）。
- **日志在不在**：目标 OSS 未开启数据事件 → 对象级读取无日志。
- **投没投/留没留**：控制面已投递 SLS；数据面无投递。
- **规则有没有**：SIEM 有 GetCallerIdentity 侦察规则，但无对象读取规则（因为无日志源）。
- **终态**：该路径「对象读取」环节**未检测到**（数据面日志缺失 + 无规则）→ `gap=1`；
  「身份确认」环节检测到（covered）。逐环节拆开判，不整条打包判。

## 9. 常见攻击路径 → 检测侧默认结论速查

| 攻击路径 | 关键动作默认留痕 | 常见检测侧结论 |
|---|---|---|
| AK/SK 泄露 → 对象读取 | 身份确认留、对象读取不留 | 部分缺口（对象读取 gap=1） |
| 元数据 SSRF → 角色接管 | 控制面几乎不留 | 未检测到（缺 Flow/主机/应用日志）gap=1 |
| IAM 提权/后门 | 控制面留（默认） | 通常检测到，除非无规则/未投递 |
| 公开桶配置缺陷 | 控制面策略变更留 | 通常检测到（有告警则 covered） |
| 安全组放行 | 控制面留 | 通常检测到 |
| 容器逃逸/集群提权 | K8s 审计留（需开启） | 取决于审计日志是否开启并投递 |
| 关闭审计（反取证） | 控制面留（默认） | 通常检测到（需告警规则） |

> 与其它手册的关系：判定「应留什么日志」查 `cloud-audit-log-systems.md`；判定「对应什么
> 规则」查 `cloud-detection-rule-design.md`；判定「投递与告警基线」查
> `cloud-monitoring-alerting-baseline.md`；三态结论落到 C5 门的 `detection-gap.md`。
