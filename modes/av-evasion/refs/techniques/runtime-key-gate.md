# 运行时密钥门禁（Runtime Key Gate）

> 定位：**分析准入**层——不是"规避检测"，而是控制"谁有资格让程序开始工作"。
> 与加载器解密（`lab/05`）的关系：05 解决"怎么解密"，本篇是"解密的前置条件"。
> 伴生实现：`lab/11-runtime-key-gate/`（单门）；组合前置链（时钟对表→门禁，先环境后身份）见 `lab/12-gate-chain/`。

## 原理

在**敏感配置解密之前**设一道门禁：程序启动先做密钥判定，密钥匹配才继续初始化并解密
内嵌配置（C2 地址/回连参数等）；不匹配则**静默退出（exit 0）**——不报错、不落盘、
不自删除、不产生任何网络行为。分析者视角"什么都没发生"，极易误判为损坏样本或空壳。

三个核心设计维度（缺一弱一档）：

| 维度 | 设计 | 为什么 |
|---|---|---|
| **门禁位置** | 先于配置解密 | 密钥错误时敏感配置**从未进入内存**——即使样本被截获、被完整内存取证，也拿不到基础设施信息。防护上限由位置决定：放在解密后就只剩"加密的配置"，放在解密前是"从未存在的配置" |
| **判定纯内存化** | 输入源收窄为 argv（启动参数/argv[0]）/ 环境变量 / 内嵌配置自检（如"仅配置指定主机激活"）——全程零文件读取、零网络探测、零硬件指纹系统调用 | 判定不留系统调用痕迹，分析者用排除法（无文件 open/无 socket/无 uname·网卡·序列号探测）**无法定位输入源**；三类来源在 trace 层不可区分 |
| **失败语义** | 静默干净退场 exit 0 | 诱导"空样本/损坏样本"误判，分析者可能直接放弃或归档，不做深挖 |

**解锁路径=操作级**：操作员通过已控主机的 shell 以正确参数/环境变量启动——门禁不依赖
任何辅助文件或驻留组件（那会留下可分析的依赖关系），只依赖"操作员知道密钥"。

## 实证特性（该类样本的可验证行为特征）

- 门禁失败样本的完整系统调用序列中：**0 次 socket/connect、0 次 pipe/socketpair、
  0 次密钥类文件 open、0 次 uname/网卡/序列号探测**——判定发生在纯内存；
- 退出瞬间的完整内存转储中**无任何 C2 字符串**（门禁先于配置解密的直接证据）；
- 无 fork/setsid（未守护化）、零落盘——失败路径与成功路径在"是否继续"上分叉，
  失败路径本身极简。

## 组合链（前置链）

门禁通常不单独存在，与反沙箱前置串联：

```
启动 → 反沙箱检测（时钟对表：双线程比对 CLOCK_MONOTONIC/CLOCK_REALTIME 流逝一致性，
       打"快进时间"类沙箱）→ 运行时密钥门禁（本篇）→ 配置解密 → 守护化 → 回连
```

时钟对表覆盖"环境真假"，密钥门禁覆盖"操作者真假"——两道门都过才进入工作态。

## 检测侧配对（技术与检测成对纪律）

| 侧 | 对策 |
|---|---|
| 沙箱自动化 | ①**同族交叉验证**：同家族其他样本可跑通而本样本静默 exit 0，排除"空壳/损坏"误判（这是定位门禁的关键动作）；②argv/环境变量**模糊空间探测**（对启动参数与常见环境变量做受控枚举重放）；③指令级（qemu/unicorn）跟到门禁分支，**patch 跳转**后重放——门禁是纯内存分支，patch 成本低 |
| 静态分析 | 混淆剥离后的结构特征：独立的环境校验函数族命名残留（envcheck/protection/runtime_key 类 pclntab 符号）；门禁函数引用内嵌密文 blob 但失败路径不触解密函数的调用图形态 |
| 行为侧 | **"过干净"本身就是 IOC**：现代真实样本几乎都有外联/落盘尝试，一个"零外联零落盘零报错 exit 0"的可疑 ELF 反常——蓝队侧应把"太干净"列为深挖信号而非放行信号 |
| 内存取证边界 | 门禁在解密前 → 主机侧取证拿不到 C2，**必须靠旁证**：流量侧（长周期抖动重连/纯 IP 直连特征）、进程父子关系与启动时环境变量（auditd EXECVE/shell history/systemd unit/cron 定义） |

## 变体谱系（设计空间）

- 输入源变体：argv[0] 伪装名校验 / 特定环境变量存在+值校验 / 内嵌配置主机绑定（机器
  指纹在投放前烧录，运行时纯内存自检）/ 多因子（参数+环境变量同时匹配）；
- 失败变体：静默 exit 0（首选）/ 延时后退出（叠加时间成本）/ 演进为"假工作态"
  （错误密钥下执行无害 decoy 行为，消耗分析时间）；
- 位置变体：门禁后移到"首次任务下发前"（延长取证窗口内的假象）/ 多门禁串联
  （不同模块各自校验，绕过一处不够）。

## 工程注意

- 门禁密钥本身随载荷混淆层（符号/字面量加密）保护——密钥明文不应出现在静态可见区；
- argv/env 校验值与操作侧 SOP 必须配套（操作员启动命令进交付文档），否则投放后无法
  解锁；
- 对抗成本评估：门禁对"指令级动态分析+patch"无免疫力（纯内存分支可 patch）——它的
  真实价值是抬高**自动化分析**（云沙箱/批量分类）的成本，不是对抗人工逆向。
