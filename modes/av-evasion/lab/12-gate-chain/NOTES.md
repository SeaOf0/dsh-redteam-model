# 12 组合前置链（反沙箱时钟对表 → 运行时密钥门禁）· 技术↔检测侧配对表

原理篇：`../../refs/techniques/runtime-key-gate.md`（组合链节）；单门实现见 `lab/11`。

## 演示内容

| 步骤 | 命令 | 预期 |
|---|---|---|
| 构建 | `cc gate_chain.c -o gate_chain -lpthread` | 纯 C 跨平台 |
| 环境过+密钥错 | `./gate_chain wrong` | 先过 ~2s 时钟对表，再静默 exit 0 |
| 环境过+密钥对 | `RUN_KEY=demo-key-2026 ./gate_chain` | 打印解密后的演示配置 |
| 模拟快进沙箱 | `cc -DDEMO_SIM_FASTFORWARD … && RUN_KEY=demo-key-2026 ./gate_chain` | **密钥正确也被环境门拦**（静默）——证明门序 |

## 链序设计（先环境后身份）

实战样本观测序为**先时钟对表、后密钥门禁**，理由：

1. 沙箱里连**密钥判定的存在性都不暴露**——时间侧信道（密钥判定引入的时序差异）不留给沙箱；
2. 成本不对称：环境门挡掉全部自动化分析（量大），密钥门只挡人工/定向（量小）——便宜的门放前面；
3. 累积失败形态一致（任一门都静默 exit 0），分析者无法从行为分辨"死在哪道门"。

## 技术↔检测侧配对

| 技术侧设计 | 检测侧对策（实验时逐条自验） |
|---|---|
| 时钟对表（双时钟交叉+睡眠时长核对） | 真实时钟沙箱（不快进）；指令级框架（qemu/unicorn）直接 hook clock_gettime 返回伪造一致值 |
| 密钥门禁（纯内存零系统调用） | argv/env 受控枚举重放；trace 门禁分支 patch（见 lab/11 NOTES） |
| 链序先环境后身份 | patch 掉第一道门后重放，观察是否出现"新的静默退出点"——**逐门剥离法**定位门数 |
| 任一门失败均静默 exit 0 | "过干净=IOC"（同 lab/11）；同族对照排除空壳误判 |

## 挂载点契约（对接真实载荷形态）

`payload_mount()` = 两门全过后的唯一入口：真实形态此处对接 `lab/05` 的解密执行段
（加密载荷 blob 与解密器都在该骨架内，载荷自备）。组合后完整时序：

```
启动 → 时钟对表 → 密钥门禁 → [此刻] 配置+载荷密文才进内存解密 → 执行
```

## 边界如实登记

- 演示窗 2 秒（真实形态数十秒级），容限 200ms 为教学值——真实参数按目标沙箱实测调；
- 时钟对表对"真实时钟沙箱"与"指令级伪造一致时钟"均无免疫力；门禁链的价值=分层抬高
  自动化分析成本，不防决心明确的人工逆向；
- 本骨架零恶意功能（演示载荷为占位串）；检测侧对策未在判定环境实测前不入镜像表。
